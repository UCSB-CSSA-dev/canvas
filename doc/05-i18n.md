# 05 Internationalization (中英双语)

## Summary

- **Chinese (`zh`, Simplified) is the default.** English (`en`) is the secondary language.
- Users switch with a "中 / EN" toggle. The choice is saved to `localStorage` and to `users.locale`.
- Code, comments, docs, identifiers, and commit messages are in English. Only user-facing strings are translated.
- Library: [`next-intl`](https://next-intl.dev), used **client-side only** (`NextIntlClientProvider`) because the site is a static export.

## Locale selection

There is no locale segment in URLs (a static export has no middleware to detect or rewrite it), so `/chat/` serves both languages.

- The locale lives in `localStorage` under `cssa-hub-locale`, read with `useSyncExternalStore` (`frontend/lib/locale-store.ts`). Prerendered HTML is always `zh`; the stored choice applies on hydration.
- Order: stored choice, then `users.locale` after sign-in (copied into storage only when nothing is stored yet, e.g. a new device), then `zh`.
- The toggle (`frontend/components/layout/language-toggle.tsx`) updates storage, which re-renders every subscriber, and calls `users.setLocale` when signed in so emails use the same language.
- `I18nProvider` sets `<html lang>` to `zh-CN` or `en` and uses the `America/Los_Angeles` time zone.

## Files

```text
frontend/

  scripts/check-i18n.mjs                   # CI: both files have identical keys
```

## Message keys

- Nested by feature, then component or purpose: `chat.composer.placeholder`, `files.upload.tooLarge`.
- Keys are English, `camelCase`, describe meaning (not the text). Good: `assignments.status.changesRequested`. Bad: `assignments.pleaseRevise`.
- Shared words go in `common`: `common.save`, `common.cancel`, `common.delete`, `common.confirm`.
- Use ICU message syntax for variables and plurals:

```json
{
  "chat": {
    "unread": "{count, plural, =0 {没有未读消息} other {# 条未读消息}}",
    "composer": { "placeholder": "发送消息到 {channel}" }
  },
  "notifications": {
    "assignment_new": "{by} 给你布置了任务「{title}」"
  }
}
```

```json
{
  "chat": {
    "unread": "{count, plural, =0 {No unread messages} one {# unread message} other {# unread messages}}",
    "composer": { "placeholder": "Message {channel}" }
  },
  "notifications": {
    "assignment_new": "{by} assigned you \"{title}\""
  }
}
```

### Rules for agents

1. Never hard-code display text in components. Use `useTranslations("namespace")` in client components. Server components can't know the locale, so they must not render translated text.
2. Every new key goes into **both** `zh.json` and `en.json` in the same change. Write the Chinese first, as it is the primary UI.
3. Keep both files in the same key order. CI (`npm run check:i18n`) fails when keys differ.
4. Server errors: Convex throws `ConvexError({ code })`. The client maps `code` to `errors.<code>` keys with `useErrorToast()` (`frontend/lib/errors.ts`). Do not send translated text from the server.
5. Notification text is rendered on the client from `type` + `params` (see [notifications-and-email.md](features/notifications-and-email.md)).
6. Emails are rendered on the server in the recipient's `users.locale`, using a small dictionary in `convex/lib/emailTemplates.ts` (Convex functions cannot read the Next.js message files).

## Bilingual data in the database

Some data is created by admins and shown to everyone, so it is stored in both languages:

| Table | Fields |
| --- | --- |
| `departments` | `nameZh`, `nameEn`, `descriptionZh`, `descriptionEn` |
| `users` | `nameZh`, `nameEn` |

Display helper `localized(zh, en, locale)`: returns the value for the current locale, falling back to the other language when empty.

User-generated content (messages, file names, assignment text) is stored as written and **not** translated.

## Dates, times, numbers

- Organization time zone: `America/Los_Angeles`. Show all times in that zone, labeled when ambiguous.
- Format with `next-intl` `useFormatter()`:
  - `zh`: `10月19日 下午6:00`, relative: `3 分钟前`, `明天`.
  - `en`: `Oct 19, 6:00 PM`, relative: `3 minutes ago`, `tomorrow`.
- Chat timestamps: time only for today, "昨天 / Yesterday", then the date.
- File sizes: `formatBytes` helper with `KB`, `MB` in both languages.

## Typography notes

- Allow Chinese text to wrap anywhere; avoid `whitespace-nowrap` on content that may be Chinese.
- Mixed text: no manual spaces between Chinese and English. Let the content be as the user typed it.
- Truncate with `truncate` / `line-clamp-*`. Chinese strings are shorter in characters but wider per character, so test both languages in narrow layouts.
